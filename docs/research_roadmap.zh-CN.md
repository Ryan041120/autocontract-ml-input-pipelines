# AutoContract：收拢后的研究路线

更新：2026-10-14。目标是用尽量少、能改变判断的研究回答中心问题；不是增加新的 freeze／receipt／审核层。本文是工作路线，不修改历史协议、阈值、split 或执行许可。

## 范围与主线

当前只聚焦固定版本的 CPU torchvision 图像预处理与 batch 消费边界。严格 S0 是参考与反例诊断；具有尺寸缩减机会的 Normalize／Crop／stack 是新的 S1 性能候选方向。两边的观察关系和结果分别报告，不把旧 S0 标签改写成 S1。

目前真正待检验的主张是：**完整分析策略能否在同等知识、信息和预算下，比强静态或源码可见的差分方法，更有效地建立可用关系或发现有意义的反例，并正确约束优化器。**共享规则和版本 hash 不能重复记作独有创新。

不继续扩展完整近数据系统、动态卸载、多框架通用化或新的控制面版本。任务级放宽语义 S2 暂列后续工作；它需要另一个统计实验，不能顺手夹进严格等价实验。

## 第一步：先检验分析方法有没有增量（现在可做）

产出一个可执行的比较 runner 和一张能否定主张的表。先把已知开发集用于调试，再隔离新的评价集合；生成策略／预算在评价集合产生前固定，不能按结果挑案例。

| 对照 | 信息与能力 | 要检验的作用 |
|---|---|---|
| 原序 fail-closed | 不授权新顺序 | 安全与机会损失的保守参考 |
| 共享规则 static-only | 同一 primitive 规则、源码与 context bindings，无算子调用 | 区分关系知识与自动策略增量 |
| 固定 stateful differential | 同一输入域、RNG／别名／异常观察与调用预算 | 反例搜索基线；阴性只是有限证据 |
| 源码可见的强差分 | 能利用与主方法相同的源码信息及预算 | 防止只赢弱探针策略 |
| 完整 AutoContract | 实际实现的证明／反例策略，证据级别如实记录 | 当前待完善，不用名字替代实现 |
| AutoContract 去掉源码引导 | 保持其他条件和总预算相同 | 解释源码引导是否有增量 |
| manual hints／human oracle | 可选，提供时记录角色与成本 | 补充比较；缺失不阻塞或虚填 |

必须记录适用域、有效关系接受、可重放反例拒绝、Unknown、Error、探针调用、预算耗尽、重新分析成本。分母按 operator family／source lineage 分组，不能把重复 seed 算成独立算子。静态和主方法共享规则时，接受相同是合理结果；没有差异就如实报告。

先明确算法变化，再运行比较。当前“源码引导”是固定选探针规则，还不是成熟自适应灰盒搜索；不能把主方法换个标签就当新实现。旧96-call开发预算与旧已知案例不能自动成为正式预算和独立 benchmark。

**停止条件：**若在同等信息下，主方法的有效覆盖、搜索／分析成本和失败行为均没有有意义的改善，不继续靠加 canary、弱化静态或改分母制造优势。转为消费边界与验证接口的技术报告；这也是合理成果。

## 第二步：把微型关系连到真实候选（可先离线论证）

2×2 CenterCrop／0.5 Normalize 的关系不能直接用于 RandomCrop224/448 和一般均值／标准差。需要先明确真实随机裁剪的参数抽样是否与 Normalize 顺序无关、裁剪坐标是否越界、逐元素浮点运算是否保持顺序，以及中间 Tensor 是否在消费者外可观察。

产出对应声明域的关系论证／检查器和受限 consumer 实现，检查入口、异常与有限串行 batch 历史。模型假设与运行 guard 分开；未证明 non-escape 或 native 语义就明示，不宣称任意 Python 所有权证明。所有方法用同一新 context，不迁移旧预测。

只有确实支持实际候选，才进入重排测量。原序 baseline 本身不需要先证明交换，可以在资源就绪后独立验证。

## 第三步：原序瓶颈与机会筛选（用户有空后）

资源准备／释放内存及真实 profiling 已延后。沿用既有四 cell、数据用途、5 warm-up＋20 measured blocks、每 block4步／batch4和停止要求。先验证真实 native pipeline，再运行原序 baseline；不启动候选，也不训练任务质量模型。

拆分读取、解码、Resize、float 转换、guard、Normalize、Crop、stack、模型更新与端到端时间，报告以 block 为单位的离散程度。CPU串行输入占比不是 GPU idle；不要泛化到分布式、冷缓存或加速器训练。

原序数据能排除缺乏机会的配置，但没有候选成本时 predicted gain 为 Unknown。既定20%暴露输入门和5%收益门保留，不看完数据再降低。原序 Normalize 的条件删除上界不是候选实测加速。

**停止条件：**预定配置都没有足够机会，就停止性能主张，保留机制与负结果。不能不断换模型直到找到正结果。

## 第四步：当前优化器路径与净收益

先验证新的 consumer 在完整 Cedar 当前 API 中只生成／选择授权候选。历史完整路径成功不等于新路径已验证；源码规划核心成功也不等于 Feature／PhysicalPlan 跑通。

实际比较原序、共享静态授权、AutoContract授权及所需消融，各 arm 采用同一消费边界、随机条件与测量规则。时间成本包括 recurring guards、额外复制／stack，以及一次性分析／规划的摊销；不要只计最有利的 steady-state 区间。

接受决策和成本选择分开：“可重排”不表示“应当重排”。无净收益时保持原序。保留失败／partial，首错停止，不删 outlier、替补 block或事后换检验。

## 第五步：只有需要放宽语义才做任务级非劣性

另定真实标签任务、训练预算、验证规则、配对初始化、重复单位、允许损失 δ 与统计功效。δ 来自任务容忍要求，不从观察到的波动选取。“差异不显著”不表示非劣；100步计时链也不是精度评价。

这一步成本最高，目前不启动。若主线采用 S1 精确 batch 关系，先完成前四步；无需为了回答老师的观点立即训练大量模型。若改走 S2，则明确研究问题已经改变，不能沿用严格 proof 的成功标签。

## 工作投入与交付物

| 先后 | 下一份交付物 | 依赖用户释放内存？ | 对研究判断的作用 |
|---|---|---|---|
| 1 | 强基线比较实现、固定预算和隔离评价设计 | 否 | 判断自动策略增量是否存在 |
| 2 | 实际 RandomCrop／Normalize／stack 的条件关系 | 离线部分否 | 防止微型证明与真实候选脱节 |
| 3 | 原序 baseline 的分解表 | 是，且恢复真实测量 | 回答瓶颈与收益机会 |
| 4 | 当前 Cedar API 验证与净收益表 | 是 | 判断系统效果是否值得 |
| 5 | 可选任务级非劣性实验 | 是，需单独设计 | 回答允许语义变化后的模型效果 |

每完成一步更新中心主张，先看结果是否改变结论。代码量、协议数量和跑通次数不是进度的唯一尺度。人工评价可选，现有 profiling 暂停独立保留。
