# AutoContract：阶段成果与研究定位

更新：2026-10-14。本文是项目现状总结，不是论文已录用、通用系统完成或独立 benchmark 通过的声明。

## 一句话定位

AutoContract 研究**机器学习输入流水线在明确消费边界下的可检查安全重排**：先确定优化器改变顺序是否保持声明语义，再判断改变顺序是否值得。当前已有原型、反例、条件模型证明和优化器规划接入；自动化优势、独立评价及稳定净收益仍未建立。

暂定研究问题：在固定版本的 CPU 图像预处理流水线中，绑定代码、参数、输入域与消费者约束的关系证据，能否保留有用的重排机会，并在同等信息和预算下表现出相对强基线的明确增量？“能否”是待验证问题，不能提前写成答案。

## 已经做出的实质工作

| 成果 | 已有证据 | 可以支持的结论 | 不能推出的结论 |
|---|---|---|---|
| 从算子属性检查走向具体关系判断 | 确定／无状态算子也不交换；状态、RNG、别名等开发反例 | 随机性／无状态不足以决定交换性 | 发现这个问题本身就是新颖算法 |
| 明确严格观察标准 | 输出字节、metadata、输入后状态、RNG、对象状态、别名、定义性和序列轨迹 | “值一样”与“声明语义一样”不同 | 任意 Python／native 上下文等价 |
| 找到旧证明口径的缺口 | 固定版本 Normalize／CenterCrop 输出值和 RNG 相同，布局不同，后续 `view(-1)` 行为不同 | 旧数值关系不能直接升级为严格 pair 等价 | 旧实验所有机制和结果都无效 |
| 受信 primitive 模型中的关系证明 | Normalize(mean=std=0.5)／Flip，p=0、0.5、1；两个符号分支 | 条件模型关系可机器检查 | 自动证明任意源码／原生内核 |
| 微型封闭 batch 片段 | Normalize(0.5)／CenterCrop(2,2)／stack，H/W=2..8；5 组开发配置和明确私有出口 | 在明示 non-escape／native 假设下的 batch 关系 | 已覆盖一般 Normalize／RandomCrop224/448 |
| 同一优化器规划核心接入 | 当前请求约束进入固定 Cedar 枚举、成本排序与选优；原序或单次交换 | 约束实际影响候选和选择 | 完整当前 Cedar API 已验证，或人工成本代表加速 |
| 统一开发比较 | 4 个已知 CPU pair；主方法、静态、两种差分、源码引导差分和 fail-closed | 可比较方法建议、调用数和规划边界 | 独立准确率、跨族泛化或总体方法优势 |
| 证据复用／失效消融 | 13 个预先声明的开发变化，10 项测试；旧证书验证仍重构符号推导 | 必要失效与可重新推导的变化已区分 | 复用是 AutoContract 独有收益 |
| baseline 测量工具准备 | 四 cell、真实47类标签配置、互斥计时、纯 fixture runner、直接温度接口开发 | 原序测量路径的实现准备有进展 | 已测得瓶颈、GPU stall 或任务质量 |

工程测试、保存后 hash 核对和符号模型检查分别验证不同东西，不能把次数相加写成“几百个独立科研样本”。本仓库的公开投影见[产物说明](PUBLIC_ARTIFACTS.md)和[机器可读成果表](../reports/research/2026-10-14/claims.json)。

## 历史性能结果必须如实保留

P5S 在固定 CPU／warm-cache DIV2K 路径上比较原序和授权重排，两 fold 的时间比中位数约为 0.9357、0.9381。但预先规定的 ratio CI 上界为 **0.9525073**，未低于 0.95，正式收益判定保持 **No-Go**。这不是“完全没有任何加速”，而是没有满足事先设置的稳定至少5%收益要求。该历史结果标记 `scientific_evidence=false`，不支持总体性能主张。

P5T 的一次8点校准中7点时间比低于1、1点略高于1；只允许逐点描述，不合并计算总体加速／显著性，也不用于选择后续 workload。两项都不能被新一轮微型证明或工具检查“洗成”成功实验。

P5Q／P5S 的训练步骤使用合成标签，是计算链一致性证据，不能称为真实分类任务精度保持。P5V 准备了 DTD 的真实47类标签及原序测量配置，但 profiling 尚未运行，真实任务质量还未评价。

## 老师的两问，目前回答到哪里

**为什么加速、瓶颈在哪、潜在收益多大？** 重复的在线预处理可能占据训练关键路径，离线训练也有资源和等待成本。这个一般动机并不能证明我们的配置有瓶颈。Normalize／Flip 不减少元素工作量，适合作为语义控制；Crop 前移可以减少后续 Normalize 的工作量，更值得测。实际节省还要覆盖 guard、stack、分析和规划成本。[cedar 的输入流水线动机](https://arxiv.org/html/2401.08895v4#S1)、[Pecan 的成本与输入等待问题](https://www.usenix.org/conference/atc24/presentation/graur)

当前只有结构机会与历史有限性能结果，还没有新的 baseline 瓶颈测量。CPU 串行输入时间不应被说成 GPU stall；原序测量没有候选成本，不能直接给出预测加速。

**什么叫安全，最终模型效果是否才重要？** 两种目标都合理，但要分开：精确语义回答优化是否改变声明行为，任务评价回答允许变化后模型指标能否接受。随机计算也有需要保持的 RNG 轨迹、状态和样本顺序；“ML有随机性”不是随意重排的理由。Pecan 采用放松交换条件并评价任务效果，支持把这条路线单独设计，不能替我们的任务作担保。[Pecan §6.3](https://www.usenix.org/system/files/atc24-graur.pdf)

| 标准 | 观察边界 | 当前状态 |
|---|---|---|
| S0 | 两算子出口的声明精确观察 | 严格参考；Crop 布局反例保留 |
| S1 | 封闭预处理＋stack 的完整 batch 出口 | 微型模型条件关系成立；真实 RandomCrop 场景待论证 |
| S2 | 允许输入变化，任务指标非劣且收益可接受 | 延后；δ、训练预算、重复与功效设计未固定 |

S1 仍要求最终 batch 精确相同。S2 才允许任务层面的变化；S2 成功不能反向抹去 S0 反例。后续所有基线必须在同一边界比较。

## 当前不能写进摘要的主张

不能写“通用自动安全重排”“已经替代人工”“稳定加速训练”“原生形式化验证”或“优于强静态／灰盒方法”。当前主方法与共享静态拥有相同的条件接受结果；源码引导 Resize 的4 calls 与固定探针的52 calls只是一个已知开发案例，不构成泛化优势。

人工 hints／human oracle 已改为可选。自动可重放反例和可检查关系证据仍然需要；自动产生数据、自动判标签并不天然意味着参考独立。未知应保留为未知。

## 建议的成果表述

适合研究经历／阶段汇报的说法：

> 开发了机器学习输入流水线重排的研究原型，明确了包含布局、随机状态与别名的观察标准，复现了数值一致但后续行为不同的反例，实现受信模型中的条件关系检查及 Cedar 规划约束接入，并保留了未达到预设端到端收益门的实验结果。当前正在通过强基线和独立案例检验自动分析的增量。
